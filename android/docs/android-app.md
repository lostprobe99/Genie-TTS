# Android 正式应用

这条分支用来做正式应用。本文是功能设计和界面示意图。合成全部在手机上完成，文字、音素、韵律、声学模型和声码器都不出手机。只做中文。

工程在 `android/app`。给人看的版本遵循 [Semantic Versioning 2.0.0](https://semver.org/spec/v2.0.0.html)，现在是 `0.0.19`。`0.y.z` 是初始开发，角色包和韵律包的格式到 `1.0.0` 才锁定。那之后，修订号加一是修问题，次版本号加一是加功能，旧包仍能用；主版本号加一是旧包不能继续用。`versionCode` 是 19，只给系统比较新旧，每次发布加一，不由这三位数字算出来。包名 `com.genie.tts`，和演示程序分开安装。韵律包和角色包在单独的资源 release `packs-0.0.1`，不跟应用安装包放在一起。

安装包不带角色，也不带韵律模型。应用使用正式签名，只安装在 arm64 手机上。更新应用不会清掉已导入的角色和韵律包。

示意图里的 Genie 是顶栏上的应用名。`( 播放 )` 表示还不能点，`[ 播放 ]` 表示可以点。`#` 是抽屉拉开后变暗的主屏。

## 代码结构

源码在 `com.genie.tts` 下按职责分包。`MainActivity` 和 `TtsService` 留在根包。`ui` 是页面，`character` 是角色包和清单，`speech` 是合成、韵律和 `g2p`，`service` 是朗读接口，`core` 是日志和机器状态。

`MainActivity` 负责应用生命周期、页面切换，以及首页、角色和韵律操作。独立页面不再把筛选状态和渲染细节塞进 Activity：

- `ServicePageController` 管服务状态、统计、地址和运行时间。
- `LogPageController` 管日志筛选、搜索和列表渲染。
- `HelpPageController` 管帮助分类、搜索和问答展开状态。
- `AboutPageController` 管版本、设备与安装信息。

合成路径和界面分开。`Speech` 组织一次合成，`ChineseFrontend` 生成中文音素，`Prosody` 生成中文韵律，`TtsEngine` 只运行角色包里的 ONNX 模型。同一角色连续几句复用已经读入的清单和参考张量。加载时不再把优化后的模型写到 `optimized/`，已有的这个目录会删掉。主屏、试听和接口的合成进同一条推理队列，同一时间只跑一路；丢掉已加载的模型也走这条队列。播放在自己的线程上，不占着合成。播放的时候可以导入、改字和打开别的页。点合成、试听或播放会先停掉正在放的声音。退到后台继续放，离开这个界面（Activity 销毁）就停。朗读接口由 `TtsServer` 解析 HTTP，`TtsService` 负责前台服务生命周期，再交给同一份 `Speech`。接口开着没有、端口、运行时间和调用统计放在一份不可变的 `ServiceState` 里。`ServiceStateStore` 可以同时通知好几处界面，注销之后就不再通知。角色文件和清单只从 `CharacterRepository` 进出，包格式集中在 `CharacterPackSchema`。

## 界面结构

四个页面从主屏进入。

- 主屏、角色管理、服务管理和韵律模型的左上角都是三横线。点它从左侧拉出抽屉，后面的页面变暗。点暗处或返回，抽屉收回。抽屉收回之后再按返回，回到主屏。关于页、使用帮助和查看日志左上角是返回，回到主屏。角色页正在批量管理时，返回先退出批量。
- 抽屉第一条是首页，点它回到合成页。下面是软件设置、角色管理、服务、韵律模型、关于。软件设置的稿在 `android/app/prototype/settings.html`，应用里点它仍提示「还没有这一页」。角色管理、服务、韵律模型和关于互相同级。服务管理右边的胶囊在没开时是灰色的「未开启」，开着时是「运行中」。使用帮助和查看日志都是单独的一页。使用帮助按 `android/app/prototype/help.html` 来做，端口、接口和模型文件用应用里的值。查看日志不进服务管理。服务管理右上角的日志图标也进查看日志。
- 选定当前角色只在主屏的下拉菜单里完成。

弹出层盖在当前页面上，不单独占一级页面：韵律告警、导入命名。

## 主屏

最上面是顶栏：左边三横线，中间应用名。

顶栏下面是角色。一个角色都没有时，这里只显示「未选择角色」，没有下拉菜单。已经导入过角色时，这里是下拉菜单，列出这些角色的名字，最后一项固定是「未选择角色」。选中最后一项，就回到没选角色的状态。

中间是多行文本框，可以打字，也可以粘贴。草稿留在手机上，下次打开还在。打开输入法时，分句列表、状态、语速和下面两个按钮先让开，输入框留在键盘上面。收起键盘后这些再回来。

文本框下面一直有分句列表。列表视口固定为三句高，标题行也是固定高度，合成前后这块和上面的输入框都不改高度。还没合成时列表是空的，标题是「分句列表（共 0 句）」。合成之后每句一行，行高相同：序号、一句文字、时长，右边一个圆的播放键。超过三句时在这块里滚动，第四句整行藏在下面，不露出半行。正在合成或正在播放的那一句用浅底标出来。合成完成的句子可以点这一行或播放键，只重听这一句，不重新合成。

分句列表下面是状态。还没合成时左边写「未合成」，右边写「分句: -/-  耗时: -  时长: -  实时率: -」。开始之后左边写成加载中、合成中、播放中或完成，右边改成分句进度、这次合成的耗时、已经出来的声音时长，以及实时率。实时率是耗时除以声音时长，小于 1 表示比播放更快。几乎没有声音、或播放被别的应用占用时，写在这一行下面。

再下面是语速滑条，然后是「合成」和「播放」。没有单独负责朗读的播放键，也没有分享。

语速默认 **1.00**，范围 0.60 到 1.40，一档 0.05。第一次安装是 1.00，之后记住上次的值。1.00 是模型自己的速度。小于 1 把语义帧拉开，声音变长，音高不变。大于 1 抽掉一些帧，声音变短。语速在合成时生效。播放不会重新套用语速。正在播放时拖动滑条，当前这段继续播，已经合成的声音也留着，新语速从下次合成开始用。没在播放时改语速，会清掉已合成的声音，需要重新合成。

合成可用的条件是：选中了一个角色，文本框不是空的，并且当前没有正在合成。选的是「未选择角色」时，合成不可用。

点合成后，合成键先变成「加载中」，状态写成加载中。每一句开始时，合成键显示当前句数，状态写成合成中，右边的分句进度跟着走。完成后状态写成完成，分句列表标出「合成完毕 · 点击单句播放」，每句右边写出时长。播放时播放键是停止，状态写成播放中，正在听的那一句保持浅底。这时候合成键仍可点，点下去先停掉播放再开始合成。这句几乎没有声音，或者播放没有真正开始，写在状态下面。

合成完成后如果改了正文或角色，播放键再次不可用，需要重新合成。没在播放时改语速也一样。正在播放时改语速不会停播，也不会清掉这段声音。

主屏不铺调试日志。应用如果在合成中途退出，下次打开时主屏第一行写「上次合成没有完成」，并带上版本。某一句失败时，说明写在那一行下面。

原型图是 `android/app/prototype/workbench.html`。稿上的版本号和耗时是示意。

## 朗读

正文按桌面端 `Utils/TextSplitter.py` 切开，界面上没有这项设置。

- 换行先去掉，换行不断句。
- 句号、问号、叹号、省略号收成一句。有效长度不到 5，就并进下一句。单独一个「好。」后面没有字，仍然留成一句。
- 逗号、顿号、分号、冒号平时不断。有效长度攒到 40，大约二十个字，再遇到这些才切开。
- 有效长度不计标点。一个汉字算 2，一个英文字母或数字算 1。

某一句得不到音素，就在那一行写「这句没有读出来」，继续合成后面的句子。

每一句合成完再进入播放，32 kHz，单声道。同一次合成里，声学模型只加载一次。有韵律模型时，参考句的韵律只算一次。换角色再合成，才重新加载声学模型，并清掉上一个角色的参考韵律。

这些没有设置项：

- 每一句送进模型前，句首加一个句号。它是开头的短暂停顿，避免第一句被吃掉，不会读成「句号」两个字。
- 温度 1.00、TopK 15、重复惩罚 1.35，直接用角色包里的原模型。
- 一句最多解码 500 步。模型自己停下就结束。
- 线程按手机核数自动取，一般是 4 到 6，界面上不显示。

## 角色管理

这一页只管理角色。没有从目录下载。顶栏左上角是三横线。批量管理时这一格变成关闭，用来退出批量。下面是已导入角色的卡片。每张卡有头像、名字、角色 id 和试听。长按打开编辑框：显示名称可以改，最多 20 个字，原来的名字更长时按原来的长度；角色 ID 可以复制，不能改。包里如果留着参考音频，这里写出文件名和时长，可以试听那个文件。可以把它设成主屏当前角色，也可以删除。保存之后主屏下拉菜单用新名字。原型图在 `android/app/prototype/roles.html`。打开先是角色列表，长按一张卡才弹出编辑框，点关闭、取消或遮罩就回到列表。批量删除和清空角色列表仍用白底确认。

角色 id 写在名字下面，例如三月七下面是 `sanyueqi`。朗读接口的 `character_name` 用这个 id，不用卡片上的名字。改名只改显示的名字，不改 id。

显示名、采样率、参考原文、目录和无图片时的扁平图标序号记在 `characters.db`。进程启动时读进内存。导入、改名、删除时改这一张表。更新到这一版后的第一次启动，会把已有的 `characters/` 扫进表里，然后删掉 `display-name.txt` 和 `avatar-icon.txt`。模型、清单、张量、参考音频和头像图片仍留在各自的角色目录里。之后启动不再扫这个目录。

右下角加号和菜单里的「导入角色模型」都是先选一个 zip。选好后弹出导入页，不是只填一个名字。上面是文件名和大小，可以重选。角色 ID 从包里读出，不能改。显示名称预先填好：这个角色已经导入过，就用现在的名字，否则用包里的名称。可以改。留空就用角色 ID。包里如果有 wav、mp3 这类参考音频，写出文件名和时长，确认导入前可以试听。确认后才写入。主屏下拉菜单显示的就是这个名字。列表里之后也可以改名。同一个角色再导入一次，导入页标题改成「更新角色模型」，按钮改成「确认更新」，并写明这会替换已经导入的同名角色。确认后只替换模型；这次填写的名字会记下来。日志写「已更新」。

一个角色包里是四个声学模型和参考音色，没有要朗读的例句，也没有韵律模型。试听用这个角色读它自己的参考句。菲比是「在此之前，请您务必继续享受旅居拉古那的时光。」三月七是「倒是不忙，可他不喜欢聊天」。

删除只删这个角色。韵律包还在。删掉的如果是主屏当前角色，主屏回到「未选择角色」。

## 服务

这一页和角色管理同级，底色也一样。顶栏左边是三横线，标题「服务管理」，右边的日志图标打开查看日志。只管理本机的朗读接口。

顶上是状态和开关。未开启时按钮是「开启」，开启后状态变成「已开启」，按钮变成「关闭」。「已开启」下面一行是钟的图标、「运行时间：」和 `hh:mm:ss`。从接口真正打开算起，改端口接着计，关掉再开从零开始。

下面三格是这次开启后的统计。总调用是已经结束的 `POST /tts`，成功、失败和客户端断开都算一次。失败不含客户端断开。音频是已经写出的时长，不满一小时写成 `分:秒`，满一小时写成 `时:分:秒`。主屏上的合成不算。关掉接口后回到 0 和 `0:00`。改端口接着计，不清零。不记字数，也不显示是否正在合成。

「网络与端口」写出本机地址 `http://127.0.0.1:端口/tts`，每条地址可以单独复制。端口默认 8001，旁边可以改，离开输入框就会记住。

- 本机地址是 `http://127.0.0.1:端口/tts`，给同一台手机上的软件用。
- 局域网地址是手机当前的 IPv4，给同一网络里的软件用。没有连上局域网时不显示这一行。
- 端口默认 8001，页面上可以直接改。范围是 1 到 65535，改完会记住。接口开着的时候改端口，会先停掉原来的端口，再在新端口打开，地址跟着变。
- 这一页不放日志。每次请求仍记在查看日志里：角色、是否拆句、每一段的原文、合成耗时和音频时长。这一段的合成时间比上一段音频更长时，会写「播放会空等」，级别是 WARN。请求前和请求后各有一行机器统计，归在性能监控：整机 CPU、本进程 CPU（100% 是占满一个核）、本进程内存、整机可用内存，以及电池温度。读得到机身或 CPU 温区时一并写上，并写系统热状态。同一份日志也在 logcat 的 `GenieTts` 标签里，级别跟写下时一致。
- 下面列出已导入角色的 id，例如 `feibi`、`sanyueqi`。这些 id 来自启动时读入内存的角色表，请求时不再扫描角色目录。请求里的 `character_name` 用这个 id，不用主屏上起的名字。还没有角色时，这里写「还没有。先在角色管理里导入」。

开启之后，通知栏留着「朗读接口开着」，正文是 `http://127.0.0.1:端口/tts`。通知里的大图标是桌面那枚浅色标志，状态栏小图标是同一枚标志的白色剪影。通知上有「停止」，点了就关掉接口，和这一页的「关闭」一样。切到别的应用、锁屏，接口仍可调用。点通知正文回到这一页。第一次开启会请求通知权限。通知没打开时，页面上写「通知没打开，系统可能会把接口收掉」。在系统设置里强制停止，或者重启手机，接口就停了，需要再点一次开启。从最近任务划掉应用时，部分手机会把接口一起停掉。

通知栏的稿在 `android/app/prototype/notification.html`。稿里并排放了折叠和展开。标志用现在的浅色底，地址用 `8001` 和 `POST /tts`，局域网例子是 `http://192.168.1.8:8001/tts`。运行时长是示意。应用里还没按展开卡片做，也没有稿上的并发上限。

接口是 `POST /tts`。请求体是 JSON：

| 字段 | 说明 |
|------|------|
| `character_name` | 角色 id，大小写不敏感 |
| `text` | 要读的中文，不能是空的 |
| `split_sentence` | 不传或 `false`：整段合成一次。`true`：按主屏同一套规则拆句 |

空文本返回 400，角色不存在返回 404，模型加载失败返回 503。响应是 `audio/wav`，16 位单声道，采样率用角色包里的，正式角色是 32000。一句算完就把这句的 PCM 写进同一个响应。客户端断开后，当前这句在解码步之间停，后面的句子不再算。

语速固定 1.00，不跟主屏上的语速。没装韵律包时仍然返回声音，停顿和重音弱一些，接口不弹告警。同一时间只合成一路。主屏正在合成时，接口会等它结束。

## 查看日志

抽屉里的「查看日志」打开单独的一页，左上角返回到主屏。顶栏标题旁边是当前版本，例如 `v0.0.19 (19)`。标题下面写出版本号、编译时间和安装时间。编译时间是打这个安装包的时间，安装时间是这台手机上次装上或覆盖这个包的时间。覆盖安装后第一次打开，日志里记一条「当前版本 …，编译 …，安装 …」，模块是应用。版本号没变、但编译时间或安装时间变了，也会记。同一次安装再打开，不重复记。右边可以刷新、导出，或复制日志文件的路径。

日志存在 `tts-log.txt`，最多 200 行、256 KB。这里按时间从旧到新排，最旧的一行是 `#001`。筛选或搜索之后，编号仍按原位置，不重新从 1 计。服务管理右上角和抽屉里的「查看日志」都进这一页，返回回到主屏。

每行在文件里写成 `日期 时间 级别 模块 正文`，例如 `2026-11-01 21:11:02.123 INFO 性能监控 请求后 …`。日期是 `yyyy-MM-dd`。级别和模块在写下时就定好，页面直接读这两项，不再从正文猜。页面上日期和时间分两行，级别是色标，模块用方括号。更早、只有时间的旧行仍能打开，缺的日期留空，级别和模块按当时的正文补上。

模块有这些：

- 服务：接口打开、关闭，端口被占用或没有打开。
- Web：HTTP 请求、状态码、完成或客户端断开。
- 语音合成：加载模型、解码步、每一段耗时、主屏合成和试听。
- 性能监控：开机、请求前、请求后的 CPU、内存、温度。读不到时是 WARN。
- 角色管理：导入、更新、改显示名、删除。
- 韵律：下载、导入、删除。
- 应用：覆盖安装后的版本、编译时间和安装时间。

级别也在写下时分开。DEBUG 是解码步。INFO 是正常过程。WARN 是播放会空等、声码器改用 CPU、客户端断开、机器读不到，以及主屏有句子没读出来。ERROR 是 4xx、5xx、接口没打开、导入或合成失败。

上面的级别可以同时开着几个。点一个已亮的级别就把它关掉，其他级别不动。点「全部」会把四个级别都打开。刚进这一页时 DEBUG 是关的，解码步那些 `decoder` 行先不占屏幕；要点开 DEBUG 才看得到。搜索仍然按模块和正文。列表只画屏幕上看得到的几行，滑走的行会拿来复用。长按一行复制这一行。自动滚动默认开着，新的一行会跟到末尾；关掉之后，新日志不再把列表拽到底。改筛选或搜索时回到列表开头。刷新会重新读文件，并滚到末尾。

底部写出真实的条数和文件大小。顶上的横幅写出本进程 PID，以及 `Debug.MemoryInfo` 的内存。接口开着时写「接口开着」，没开时写「接口未开启」。复制全部和导出为文本都是全部已存的行，从旧到新，不只是屏幕上筛出来的那些。导出交给系统保存对话框，建议文件名 `genie-log.txt`。还没有日志时，复制、导出和清空都只提示「还没有日志」。清空要先确认。

稿在 `android/app/prototype/logs.html`。稿上的版本号、PID、条数和示例句子是示意，应用里不用那些数字。

## 使用帮助

抽屉里的「使用帮助」打开单独的一页，左上角返回到主屏。上面可以搜索问题，也可以按新手上手、阅读/Legado、后台保活、模型导入、服务管理筛选。三步指引一直留着：导入角色、安装韵律、在服务管理开启朗读接口。

问答按原型分成对接、后台、角色、韵律和端口。文案里的端口用当前服务端口，默认仍是 8001。复制配置写出当前的 `POST http://127.0.0.1:端口/tts`，以及 `character_name`、`text`、`split_sentence`。韵律地址是 `packs-0.0.1` 的 prosody.zip，大小 599,034,176 字节。角色文件名、采样率 32000、通知文案都和现在的应用一致。

底部「仓库」打开 GitHub。 「韵律包」打开这份 zip。 「查看日志」进入查看日志页。页脚是当前版本，以及 ONNX Runtime 1.22.0 · arm64-v8a。顶栏刷新只报出已安装的版本，应用不在线检查更新。旁边的问号打开仓库。

稿在 `android/app/prototype/help.html`。

## 韵律模型

韵律模型单独成一页，和角色管理同级。它不是角色，不能被选成说话人。所有中文角色共用这一份。

页面底色和角色管理一样。顶栏左边是三横线，标题，以及「已就绪」或「未安装」。

卡片上是这份文件的真实信息：文件名 `model_fp16.onnx`、占用空间、应用私有目录里的路径（可以复制）、上次写入时间。路径不在外部存储。没有版本号、校验值和镜像切换。

操作有三块。从 GitHub 下载，地址仍是下面的 `prosody.zip`，大约 571 MB。下载时在「已下载」下面有一条进度条，中断后再点会从已下载的部分继续。已经装好时，这个按钮写成「已安装」；再点会先确认，确认后会删掉本地这份再下载。从本地文件导入，可以选这个 zip，也可以直接选 `model_fp16.onnx`。文件已经在时可以删除，先弹出和角色删除一样的浅色确认。删掉后停顿和重音会弱一些，已导入的角色还在。关于里不再写文件大小。

模型文件大小必须是 599,034,176 字节。对不上就视为没装好。再次导入会替换原来的那一份。

韵律包和角色包在单独的资源 release 里，不跟应用安装包放在一起。文件名固定是 `prosody.zip`，根目录只有 `manifest.json` 和 `model_fp16.onnx`。应用里的下载地址是：

https://github.com/lostprobe99/Genie-TTS/releases/download/packs-0.0.1/prosody.zip

不使用 `releases/latest`，也不使用演示程序的 `android-*` 标签。角色包在 `packs-0.0.1` 里是 `feibi.zip` 和 `sanyueqi.zip`。用 `android/tools/pack_android_prosody.py` 从那份 599,034,176 字节的模型打出 `prosody.zip`。

删除只去掉韵律包，已导入的角色还在。删掉角色，韵律包还在。

没装韵律模型也允许合成。点合成或试听时，如果韵律包不在，先弹出告警，先不开始合成。

> 还没有韵律模型
> 可以朗读，但停顿和重音会弱一些。
> 继续合成　　去添加

点「继续合成」，这一次合成照常进行，后面的句子不再重复弹窗。这一轮里，每一句的韵律和参考句的韵律都用全零。声音还在，音色仍来自这个角色的参考录音。点「去添加」，打开韵律模型这一页，这次不合成。

下次再点合成，如果还是没装，告警再出现一次。这不记成失败。试听用同样的告警，按钮是「继续试听」和「去添加」。

装了以后，合成前不告警。每一句用韵律模型算自己的停顿和重音。参考句的韵律按角色包里的原文算一次，同一轮合成里一直复用。

韵律模型已经安装，但参考音素和角色包里的原文对不上时，不合成这一次，并提示重新导入这个角色。这和没装韵律包是两件事。

## 关于

关于单独成一页，底色和角色管理一样。顶栏是返回和标题。版式跟着原型：顶上是标志、GenieTTS、版本胶囊和一句标语，下面三列是 cpu架构 ARM64-v8a、这台手机的 Android 版本、ONNX v1.22.0。标志底是浅青到白。桌面图标和侧栏左上角用同一套浅底，不再铺深色圆。

「这台手机」写机型、当前角色、安装时间。安装时间是这台手机装上或更新这个包的时间。

「版本与开源信息」用图标行写软件版本、构建时间、包名，以及仓库 `https://github.com/lostprobe99/Genie-TTS`。构建时间是打这个安装包时的时间。可以复制。仓库右边是指向右上角的箭头，点它打开仓库。许可胶囊写 MIT。

「技术架构与引擎」三行：本机 ONNX Runtime、中文韵律、朗读接口 `POST /tts`。没有 WebSocket。

「致谢与隐私」写合成不把文字和声音传到应用自己的服务器。接口开着时，同一台手机或同一个局域网里的软件可以来要声音。从 GitHub 下载韵律包时会联网。致谢只写 ONNX Runtime 和角色包里的 VITS。页脚是 MIT，版权 2025 High_Logic。

没有检查更新，也不写「已是最新」「稳定版」、延迟、Apache 或另一套仓库地址。

## 软件设置

抽屉里「软件设置」的稿在 `android/app/prototype/settings.html`。顶栏标题是「设置」。稿上有推理线程、长句自动分句、浅色 / 深色 / 跟随系统、开机自启动和备份恢复。页脚的 v1.7.5、ONNX Runtime 1.16，以及「WebTTS」是稿上的字。应用里点这一项仍提示「还没有这一页」，这些控件还没有。

## 第一次使用

1. 打开应用，主屏角色处是「未选择角色」。
2. 打开抽屉，进入角色管理，从本机文件导入一个角色并起名。
3. 回到主屏，在下拉菜单里选中它，输入文字，点合成。
4. 没装韵律包时会看到告警，继续就能出声。合成完成后，播放键可用。
5. 想要正常的停顿和重音，再从抽屉进入韵律模型，下载或导入。

# Android ONNX 实测 Demo

下一步要加的第二个中文角色，写在 [android-agent-handoff.md](android-agent-handoff.md)。那份是给下一个 agent 的交接。

在真机上跑通菲比。输入框里打中文，点「合成」。一段话先按原仓库的 `TextSplitter` 切开，一句合成完就播放，再合下一句。每一句由手机自己变成音素，再用中文 RoBERTa 填这一句的 `text_bert`。参考句的 `ref_bert` 只算一次。然后交给 T2S 和声码器。参考音色仍用已经放在手机里的录音特征。NPU 不在这次范围内。

## 已完成的导出

导出目录是 `android_case/`。角色是预置中文角色 **feibi**（V2ProPlus）。合成文本是：

> 今天天气不错，我们出去走走吧。

推理时按 `Core/Inference.py` 在句首加一个句号，实际送进模型的文本是 `。今天天气不错，我们出去走走吧。`。采样率 32 kHz。菲比参考句的原文是「在此之前，请您务必继续享受旅居拉古那的时光。」这句不加句首句号，对应测试包里的 42 个音素。韵律模型在的时候，目标句和参考句的 BERT 都由手机现算。模型还没下载时，两块都保持全零，合成仍能出声。

`desktop.wav` 是桌面端原始合成。`replay.wav` 是只加载导出文件重跑的结果，两者逐样本一致，最大误差为 0。

### 模型

四个声学文件都是灌好 FP16 权重的自包含 FP32 ONNX，不依赖外部 `.bin`。

| 文件 | 大小 |
|---|---|
| `models/t2s_encoder_fp32.onnx` | 11 MB |
| `models/t2s_first_stage_decoder_fp32.onnx` | 293 MB |
| `models/t2s_stage_decoder_fp32.onnx` | 293 MB |
| `models/vits_fp32.onnx` | 239 MB |

韵律模型是 `roberta/model_fp16.onnx`，599,034,176 字节。权重是 FP16，输出仍是 float32，形状 `[token 数, 1024]`。分词表打进安装包。仓库里按约 45 MB 一片放在 `roberta/chunks/`，说明在 `roberta/parts.json`。手机上拼好以后，文件大小已经对上的不会再下。声学模型不用为了韵律重新下载。

### 数组

`manifest.json` 记录每个数组的文件名、dtype 和 shape。

| 名字 | dtype | shape | 作用 |
|---|---|---|---|
| `ref_seq` | int64 | `[1, 42]` | 参考句音素 |
| `ref_bert` | float32 | `[42, 1024]` | 参考句 BERT。包里的文件仍是全零；韵律模型在时，应用按参考句原文现算后送进编码器 |
| `ssl_content` | float32 | `[1, 768, 231]` | 参考音频的 HuBERT 特征 |
| `ge` | float32 | `[1, 1024, 1]` | V2ProPlus 音色向量 |
| `ge_advanced` | float32 | `[1, 512, 1]` | V2ProPlus 音色向量 |

导出目录里还有天气这句的 `text_seq`、`text_bert`，以及 `text`、`infer_text`。角色包不带这四项。要合成的句子由输入框决定，`text_seq` 和 `text_bert` 在手机上现算。

## 手机应用

工程在 `android/onnx-demo`，包名 `com.genie.onnxdemo`，只保留 `arm64-v8a`。当前安装包版本是 1.20。依赖是 `com.microsoft.onnxruntime:onnxruntime-android:1.22.0`。

安装包里没有角色。点「导入角色包」选一个 zip，列表里就多一个角色。同一个 `id` 再导一次只替换这一份。

从手机上的 1.13 换成这一版，要先卸载再安装。两版调试签名不同，Android 不允许直接覆盖。卸载会清掉应用里已经下好的菲比和韵律模型，装好后重新导入角色包，并再点一次「下载韵律模型」。这一版之后的包都用仓库里的 `debug.keystore` 签名。已经装上 1.14 或之后版本的话，直接覆盖安装，已导入的角色和韵律模型都还在。

角色包用 `tools/pack_android_character.py` 生成。zip 里是 `manifest.json`、四个自包含 FP32 ONNX，以及 `ref_seq`、`ref_bert`、`ssl_content`、`ge`、`ge_advanced`。不写 `text`。`id` 用小写，菲比是 `feibi`，三月七是 `sanyueqi`。

没有电脑时，用手机浏览器打开安装包并安装，安装时允许未知来源：

https://github.com/lostprobe99/Genie-TTS/raw/cursor/android-onnx-demo-doc-3875/android/onnx-demo/genie-onnx-demo.apk

点「下载韵律模型」，应用自己把中文 RoBERTa 拉下来，大约 572 MB，所有角色共用。中途断了再点一次，已经拼好的不会再下。拼好以后大小是 599,034,176 字节。如果点「合成」后应用退出，重新打开，日志里会写上次停在哪一步。

点「参数」展开。里面是语速、分句最短、分句最长、解码步数、线程。默认和桌面端 `tts()` 一样：语速 1.00、分句 5 和 40、解码最多 500 步、线程自动。语速小于 1 会把语义帧拉开，音高不变。解码步数是一句最多生成多少个语义帧，一步约 40 毫秒；模型自己停下时用不到这个上限，调小到句子所需步数以下才会把后半句截掉。温度 1.00、TopK 15、重复惩罚 1.35 写在两段解码模型里，菜单里没有这三项。每一句仍在句首加一个句号，和 `Core/Inference.py` 一样，菜单里也不能关。1.18 曾经写过的解码副本会在打开应用时删掉。三月七念天气这句在语速 1.00 时大约 2.2 秒。

换句子直接改输入框。一段话先按桌面端 `Utils/TextSplitter.py` 切开，再逐句合成。规则和桌面端默认的 `tts()` 一样：句号、问号、叹号、省略号收成一句；这一句有效长度不到 5，就并进下一句；逗号、顿号平时不断，有效长度攒到 40（大约二十个字）再遇到逗号才切开。换行先删掉。只有一句时，行为和以前一样，仍保存成 `phone.wav`。多句时日志先写「分成 N 句」，每一句写「第 i/N 句」，这一句播完才合下一句，音频分别存成 `phone-1.wav`、`phone-2.wav`。参考韵律仍只算一次。每一句送进模型前仍在句首加一个句号，和 `Core/Inference.py` 一样，然后在手机上做分词、多音字、变调和儿化。日志里会写出归一化文本、音素个数和音素。下面三句已经和桌面前端对过。「一日还」是 `h ai2`，「朝霞」是 `zh ao1 x ia2`。天气那句和七言、论持久战各是一句，音素个数应是 29、31、41。洛神赋原文中间有句号，会分成两句先后播放，每一句自己再在句首加句号，所以不再是原先整段的 49 个音素。

- 朝辞白帝彩云间，千里江陵一日还。
- 远而望之，皎若太阳升朝霞。迫而察之，灼若芙蕖出渌波。
- 战争的伟力之最深厚的根源，存在于民众之中。

天气那句是 29 个音素：今天天气不错，我们出去走走吧。

韵律模型在的时候，日志里会有「韵律 N ms」和「参考韵律 42，N ms」。参考句只算一次，第二次变成「参考韵律 42」。连点两次「合成」，第二次才把加载时间摘出去。第一次会把韵律模型读进内存，并一直留着，下次点「合成」不用再读。如果日志写「韵律模型还没放进来」，就是还没下完，这时两块 BERT 仍为零。如果写「韵律对齐不上」或「参考韵律仍为零」，对应那一块退回全零，不会闪退。

在装好 Android SDK 的电脑上也可以自己编译：

```bash
cd android/onnx-demo
gradle :app:assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

声学模型和韵律模型都不要打进 APK。中文前端的词典、拼音表和 RoBERTa 分词表打进安装包。界面上有输入框、角色列表、「导入角色包」、「下载韵律模型」和「合成」。先选中一个已导入的角色，再按下「合成」：

1. 用 `TextSplitter` 把输入切开。参考音色按 `manifest.json` 读入：`ref_seq`、`ssl_content`、`ge`、`ge_advanced`。韵律模型在的话，用参考句原文现算一次 `ref_bert`，并确认音素编号和包里的 `ref_seq` 一致。对不上就继续用包里的全零。
2. 每一句用输入框里的这一截现算 `text_seq`。韵律模型在的话，用归一化后的这一句跑 RoBERTa，按每个字对应的音素个数把 1024 维特征铺开，得到 `text_bert`。模型不在，或对不齐，就造一块全零的。
3. 依次运行 encoder、first-stage decoder、stage decoder、VITS。stage decoder 一步一个语义 token，直到停止标志为真，最多 500 步。这个上限按句计算。停止条件和张量顺序与 `Core/Inference.py` 的 `t2s_cpu` 一致。
4. VITS 输入是 `text_seq`、预测出的语义 token、`ge`、`ge_advanced`。
5. 用 `AudioTrack` 播放这一句的 32 kHz、单声道、float PCM。播完再处理下一句。

执行放在后台线程。解码循环把上一步的输出张量直接送给下一步，不再每步拷贝 48 块缓存。声码器优先使用 XNNPACK，打不开时退回 CPU。文本编码、两段解码和韵律模型仍用 CPU。线程数设成大核数量，一般是 4 到 6。

日志分开记：

- 分成几句，以及当前是第几句
- 前端加载时间（只记第一次）
- 归一化文本、音素个数和音素
- 韵律模型加载时间（只记第一次）
- 目标句韵律计算时间
- 参考句韵律计算时间（只记第一次）
- 声学模型加载时间
- encoder 时间
- decoder 步数和总时间
- 声码器时间
- 端到端时间
- 音频时长
- 实时率 = 计算时间 / 音频时长
- 出错时先写版本和运行环境：版本号、Android 版本、机型、ABI、核心数、内存上限、当前角色、韵律模型是否已在

第一次运行包含图优化和把韵律模型读进内存。和桌面端对比、以及记录耗时，都以第二次为准。

## 通过标准

单独输入天气、七言或论持久战，日志是「分成 1 句」「第 1/1 句」，音素个数是 29、31、41，音素与桌面前端一致。「一日还」是 `h ai2`。洛神赋会写成「分成 2 句」，第一句里「朝霞」仍是 `zh ao1 x ia2`。韵律模型下好以后，每一句的日志里有「韵律 N ms」，不再写 text_bert 仍为零。多句时第一句播完才出现下一句的「第 i/N 句」。第二次运行的分段时间仍以日志为准。解码采样有随机性，同一句的步数和时长可以不同。
